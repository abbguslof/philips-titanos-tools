## The NDAL V4L2 reset route

The vendor reset functions are:

| Function | Address | Notes |
| :--- | ---: | :--- |
| `PLAT_SYS_ResetByHWWDT_PowerOnEventACOn` | `0xb6ad1` | `libplat.so` |
| `NDAL_VideoExt_STBC_ResetByHWWDT` | `0x137f0` | `libNDAL_EX.so` |
| `NDAL_VideoExt_STBC_ResetByHWWDT_WithPowerOnEventACON` | `0x13854` | `libNDAL_EX.so` |
| `ndcommon_v4l2_config_ctrl` | `0x27554` | `libNDAL_EX.so` |
| `ndcommon_v4l2_config_ctrllist` | `0x27534` | `libNDAL_EX.so` |
| `ndcommon_v4l2_ioctl` | `0x27574` | `libNDAL_EX.so` |
| `ndcommon_v4l2_set_fd` | `0x275d4` | `libNDAL_EX.so` |
| `Hal_VideoDec_v4l2_set_ctrls` | `0x278d0` | `libNDAL3.so`, standard `VIDIOC_S_CTRL` |

`libNDAL_EX.so` SHA-256 `4aef83c1…`; `libNDAL3.so` SHA-256 `72dee768…`. Both
are 32-bit ARM EABI5, not stripped.

`nm -D libNDAL_EX.so` lists all four `ndcommon_v4l2_*` symbols as defined
(`T`): `config_ctrl` `0x27555`, `config_ctrllist` `0x27535`, `ioctl` `0x27575`,
and `set_fd` `0x275d5`. The odd addresses are the Thumb-bit form; the even
addresses in the table are the canonical entries. The `0xb3b0`/`0xb710`/`0xbc5c`
callees are PLT stubs, not the function bodies. `v4l2_open`/`v4l2_ioctl` remain
imports.

The V4L2 bridge uses `/dev/video%i` (`.rodata` `0x2ca54`), `gv4l2_dev_name`
(`0x2cbd0`), `gfd_v4l2` (`0x50d98`), `gv4l2_dev_open` (`0x51f2c`/`0x52354`), and
in `libNDAL3.so` `gv4l2_dev_index` (`0x38938`), `g_v4l2_fd` (`0x56608`), and
`g_v4l2_fd_common` (`0x6c68c`). `libNDAL_EX.so` imports `v4l2_open` and
`v4l2_ioctl`; their provider is not in the pulled libraries.

## Exact reset call

`NDAL_VideoExt_STBC_ResetByHWWDT_WithPowerOnEventACON` (`0x13854`) builds two
16-byte controls and issues the V4L2 ioctl:

```text
config_ctrl(id=0xf17f1f, ctrl1, value=0, count=1)
config_ctrl(id=0xf17f1f, ctrl2, value=1, count=1)
config_ctrllist(which=0x0f170000, list, ctrl1, count=2)
ioctl(0xc0185647, list)
```

Observed constants:

| Field | Value |
| :--- | :--- |
| control id | `0xf17f1f` |
| control class/`which` | `0x0f170000` |
| ioctl | `0xc0185647` |
| `config_ctrl` layout | `[0]=id`, `[4]=count`, `[8]=0`, `[12]=value` |
| `ndcommon_v4l2_ioctl` | calls `v4l2_ioctl(gfd_v4l2, cmd, arg)`; returns 1 unless `-1` |

The neighbouring `NDAL_VideoExt_STBC_SetMcuWoLOnOff` (`0x138cc`) uses control
`0xf17f26` and ioctl `0xc0185648`; `SetMcuWoWOnOff` (`0x13944`) uses `0xf17f27`;
`SetMcuFakeSTROnOff` (`0x139bc`) uses `0xf17f2c`. The standard
`Hal_VideoDec_v4l2_set_ctrls` (`0x278d0`) uses `VIDIOC_S_CTRL`
(`0xc008561c`) on the fd at `ctrl+0x10`.

The `0xc0185648` / `0xc0185647` pair are `S_EXT_CTRLS` / `G_EXT_CTRLS` with
the vendor class. The reset helper should try the `S` side with id `0xf17f1f`,
class `0x0f170000`, value 1. The `NDAL_VideoExt_STBC_ResetByHWWDT` (`0x137f0`)
and `PLAT_SYS_ResetByHWWDT_PowerOnEventACOn` (`0xb6ad1`) call order remains
open.

## Helper options

1. **Dynamic `libNDAL_EX.so` helper.** `dlopen` `libNDAL_EX.so` from the app
   partition, `open("/dev/video%i")`, `ndcommon_v4l2_set_fd(fd)`, then
   `ndcommon_v4l2_config_ctrl`/`config_ctrllist`/`ioctl`. This needs the TV
   libc and the `libNDAL3`/`libstdc++` dependencies.
2. **Direct V4L2 helper.** Build the 16-byte control (`id 0xf17f1f`,
   `count 1`, value 1) and the `v4l2_ext_controls` list (`which 0x0f170000`,
   count 1), open the same `/dev/video%i`, and call `ioctl(0xc0185648, list)`.
   This avoids the unresolved `v4l2_open`/`v4l2_ioctl` provider.
3. **Static armhf helper.** Same as 2, but with a minimal syscall wrapper. This
   avoids the TV libc and all shared-library dependencies.

The device index is `gv4l2_dev_index` or the app's open fd; the helper must
confirm which `/dev/video%i` the STBC control belongs to before the ioctl.
