# NDAL V4L2 reset path and the 2026-11-14 eburner retries

Status: **VERIFIED (static)** for the NDAL V4L2 functions, the exact control,
the control layout, the `/dev/video24` target, the classic eburner USB-image
initramfs, and the p9 metadata layout. **TESTED-NEGATIVE** for the paused-
`appmgr` retry, the script after the full AC-on wrapper, and the p9-metadata
entry attempts. **OPEN** for the eburner entry trigger and the `sys_run`
script.

Target: Philips `55PUS8000/12`, chassis `TPA256E`/`TPN256E`, firmware
`TPA256E_V056.002.236.191`.

The STBC + AC entry failed again with `appmgr` paused. The NDAL V4L2 reset was
the next route. The full AC-on wrapper resets the TV. One reset run left
`/swdl/autorun.upg` removed; later runs left it in place. No run produced
`PKG_SUCCESS` or the proof. The eburner entry trigger is the open blocker; the
initramfs maps the USB image path and the extraction steps.

| `NDAL_VideoExt_STBC_ResetByHWWDT` | `0x137f0` | `libNDAL_EX.so`; single `G_EXT_CTRLS` |
| `NDAL_VideoExt_STBC_ResetByHWWDT_WithPowerOnEventACON` | `0x13854` | `libNDAL_EX.so`; two controls, `G_EXT_CTRLS` |
| `NDAL_VideoExt_OpenDevice` | `0x1279c` | Opens `/dev/video%i`, sets `gfd` |
| `ndcommon_v4l2_config_ctrl` | `0x27554` | Fills one 20-byte control |
| `ndcommon_v4l2_config_ctrllist` | `0x27534` | Fills the 24-byte `v4l2_ext_controls` list |
| `ndcommon_v4l2_ioctl` | `0x27574` | `v4l2_ioctl(gfd, cmd, arg)`; returns 1 unless -1 |
| `ndcommon_v4l2_set_fd` | `0x275d4` | Sets `gfd` |
| `Hal_VideoDec_v4l2_set_ctrls` | `0x278d0` | `libNDAL3.so`, standard `VIDIOC_S_CTRL` |

`libNDAL_EX.so` SHA-256 `4aef83c1…`; `libNDAL3.so` SHA-256 `72dee768…`. Both
are 32-bit ARM EABI5, not stripped.

`nm -D libNDAL_EX.so` lists all four `ndcommon_v4l2_*` symbols as defined
(`T`): `config_ctrl` `0x27555`, `config_ctrllist` `0x27535`, `ioctl` `0x27575`,
and `set_fd` `0x275d5`. The odd addresses are the Thumb-bit form; the even
addresses above are the canonical entries. The `0xb3b0`/`0xb710`/`0xbc5c`
callees are PLT stubs, not the function bodies.

### V4L2 provider and globals

`libNDAL_EX.so` imports `v4l2_open` and `v4l2_ioctl`. The provider is
`libv4l2.so.0` (SHA-256 `9e95381a…`), which needs `libv4lconvert.so.0`. The
provider is not in `libNDAL_EX`'s `NEEDED` list; the app loads `libv4l2`
globally.

| Global / data | Address | Meaning |
| :--- | ---: | :--- |
| `_ZL3gfd` | `0x50d90` | the fd used by `set_fd` and `ndcommon_v4l2_ioctl` |
| `gfd_v4l2` | `0x50d98` | separate 24-byte object, not the ioctl fd |
| `gv4l2_dev_name` | `0x2cbd0` | 7-byte index table: `14 18 15 1c 0e 42 00` |
| `gv4l2_dev_open` | `0x51f2c`/`0x52354` | per-index open flags |
| `/dev/video%i` | `0x2ca54` | device path format |

The index table maps to the live nodes:

| Index | Node | `/sys/class/video4linux` name |
| ---: | :--- | :--- |
| 0 | `/dev/video20` | `ndp_av_atv_scart_extin` |
| 1 | `/dev/video24` | `ndp_comp_extin` |
| 2 | `/dev/video21` | `ndp-hdmi` |
| 3 | `/dev/video28` | `ndp-hdmi-switch` |
| 4 | `/dev/video14` | `imvq-mfc-dec4` |
| 5 | `/dev/video66` | `ndp_vga_extin` |

`NDAL_VideoExt_OpenDevice(handle, type)` selects the index from the `type`
argument. `type` `0xA` selects index 1 (`/dev/video24`); the app's live
`framework-daemon` has `gfd` = 61 and fd 61 -> `/dev/video24`. The helper's
`NDAL_VideoExt_OpenDevice(0, 0xA)` also opened `/dev/video24` and set `gfd`.

## Exact reset call

`NDAL_VideoExt_STBC_ResetByHWWDT_WithPowerOnEventACON` (`0x13854`) builds two
20-byte controls and issues the vendor `G_EXT_CTRLS`:

```text
config_ctrl(id=0x0f170f1f, ctrl1, value=0, size=1)
config_ctrl(id=0x0f170f1f, ctrl2, value=1, size=1)
config_ctrllist(which=0x0f170000, list, ctrl1, count=2)
ioctl(0xc0185647, list)
```

Observed constants:

| Field | Value |
| :--- | :--- |
| control id | `0x0f170f1f` (AC-on reset); `0x0f170f29` (plain reset) |
| control class/`which` | `0x0f170000` |
| ioctl | `0xc0185647` (`G_EXT_CTRLS`) |
| control stride | `0x14` (20 bytes) |
| control layout | `[0]=id`, `[4]=size`, `[8]=0`, `[0xc]=value pointer`, `[0x10]=0` |
| list layout | `[0]=which`, `[4]=count`, `[8]=error_idx`, `[0xc]/[0x10]=reserved`, `[0x14]=controls pointer` |
| value | one byte, pointer to `0` then `1` |
| `ndcommon_v4l2_ioctl` | `v4l2_ioctl(gfd, cmd, arg)`; returns 1 unless -1 |

The earlier note wrote the id as `0xf17f1f` and the controls as 16 bytes. The
disassembly shows `0x0f170f1f`, a 20-byte stride, and a value pointer. The
plain `ResetByHWWDT` uses `0x0f170f29` with one control and returns the value
byte. The neighbouring setters (`SetMcuWoLOnOff` etc.) use the `S_EXT_CTRLS`
side `0xc0185648`; the reset path uses `G_EXT_CTRLS` with the value pointers.

## The helper

A local 32-bit ARM helper used the TV's glibc 2.36 and `dlopen`:

1. `libnpc.so` (provides `_ZTI18NPCServerInterface`)
2. `libv4lconvert.so.0`
3. `libv4l2.so.0`
4. `libNDAL_EX.so`
5. `libplat.so`
6. `libutlt.so`
7. `libdev.so` (provides `_DEV_PANEL_PowerSequence`)

The helper supplies data stubs for `bplatCECIsSemiOrStandby`,
`g_b8MutexUnlockChecked`, `g_b8MutexChecked`,
`g_pstUtiliMemCheckQueueHandle`, `g_b8MemChecked`,
`gu8DebugFuncLevelControl`, and `g_b8MemProtectFlag` so `libplat` loads with
`RTLD_LAZY`. It then calls:

```text
NDAL_VideoExt_OpenDevice(0, 0xA)              -> /dev/video24, sets gfd
PLAT_SYS_ResetByHWWDT_PowerOnEventACOn()      -> full AC-on wrapper
```

The helper source and build steps are local research artifacts and are not
published. The app's AC-on upgrade variant calls this wrapper; the normal
update path calls `PLAT_SYS_Reset`.

## The eburner initramfs: USB image, not `/swdl`

The classic eburner kernel component (`eburner`, 22,566,984 bytes) is a u-boot
uImage (Linux ARM64 5.4.254). Its initramfs is a gzip-compressed cpio at
component offset `0xfd8948`; it contains `/etc/init.d/S21eburner.sh`,
`/bin/nvt_extract_sys_run`, `/bin/nvt_eburner`, and busybox.

`S21eburner.sh` does **not** read `/swdl/autorun.upg`:

```text
IMAGE_PATH=nvt_tv_firmware.img
parse /proc/cmdline for nvt_eburner_img=*
wait for /dev/sda1 and /media/sda1/${IMAGE_PATH}
nvt_ctrl_adc_reset disable
nvt_extract_sys_run ${UPDATE_FNAME}
/tmp/sys_run/run.sh ${UPDATE_FNAME}
```

The classic eburner is a USB-image updater. The app-layer `TIMGPKGVER40` path
and its `/swdl/autorun.upg` flag are a different flow. The USB image is the
full classic package (or a trimmed one); `nvt_extract_sys_run` extracts the
`sys_run` component to `/tmp/sys_run` and runs its `run.sh`. The full package's
`sys_run/run.sh` is the dump-only script; it writes `update-proof.txt` and the
boot-area images to the USB.

## p9 metadata layout

| Offset | Live p9 | Package component | Notes |
| ---: | :--- | :--- | :--- |
| `0x400` | `PPCH` pptbl0 | `pptbl0` (1536 B) | exact match |
| `0xa00` | `PPCH` pptbl1 | `pptbl1` (1536 B) | exact match |
| `0x1000` | `FWVR` vinfo | `vinfo` (512 B) | exact match |
| `0x3600` | `UPST` update status | `upst` (512 B) | live differs; package is the update status |
| `0x3800` | zeros | `bflag` (`BTFG`, 512 B) | offset inferred; absent in live |
| `0x3e00` | `_ALL_EU_...` + `PKG_ready` | app flag | `SetPKGFlag` writes here |

`libfwup.so` carries the bflag/pptbl handling: `nvtfw_get_bflag` (`0x6dbc`),
`nvtfw_emmc_read_pptbl` (`0x7d48`), `nvtfw_emmc_write_pptbl` (`0x7ea8`),
`nvtfw_emmc_sync_dbflag_boot_part` (`0xa75c`), and the `BTFG` string
(`0x198e0`). `nvtfw_emmc_write_pptbl` writes a 0x600-byte `PPCH` table at a
block offset; the live/package pptbl offsets are 0x400/0xa00. The bflag/upst
are the app-layer update metadata; writing them by hand did not enter the
eburner in the tested reset sequences.

## Reset wrappers

`DEV_UART_Set_SWEburnerOnOff` (`libdev.so` `0x49dec`) opens `/dev/ntkstbc`
O_RDWR and issues ioctl `0xc0105310` with a 16-byte struct
`00 00 00 00 c9 <arg> 00 00 c9 ...`; the `ntkctl` struct matches.

The app-layer update calls `APP_MGR_SYS_Reset` -> `PLAT_SYS_Reset`
(`libplat.so` `0xb2ee8`): panel sequence, STBC sync, `reboot(0x1234567)`.
`APP_MGR_SYS_ResetByHWWDT_PowerOnEventACOnForUpgrade` -> the HWWDT wrapper
(`0xb6ad0`). The standalone helper's `PLAT_SYS_Reset` blocked on app IPC with
`appmgr` paused; the HWWDT wrapper reset the TV.

## Safety

The probes made no boot-area or eMMC writes. The full wrapper reset wrote
`/swdl` and the p9 flag. The p9 metadata test wrote `UPST` at `0x3600` and
`BTFG` at `0x3800`; the cleanup restored the pristine p9. The USB full image
was removed. The cleanup restored the vendor `/swdl/autorun.upg` (`74d2790a…`,
917,372,175 bytes), `autorun_size.txt` (`917372175`), `autorun_version.txt`
(`940186113`), the p9 `misc` (`c32f354f…`), and the STBC mode off. The boot
areas are `eee415…`; the TV and `appmgr` run.

The local packages, helper, and libraries stay out of the repo. The note
publishes no key material.
