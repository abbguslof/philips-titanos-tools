## Browser observations on the TV

On this 55-inch unit, the browser returned an HTTP 200 version response with
Chrome 92 and Chrome DevTools Protocol (CDP) 1.3 during the USB cold-boot
test. Earlier connection attempts timed out. After the owner removed the
stick, cold-booted the TV and opened the browser again, JointSpace still
responded and the three browser-debug ports tested timed out. The attribution
to USB alone has no matched control for browser startup timing.

Doc 42 identifies the USB flag file that opens CDP on this firmware family.
Whether the field stick used here carried the flag remains **OPEN**; the
browser restart timing is consistent with it. See
[the RPC-injection root note](42-tpn236e-43pus7608-rpc-injection-root-2026-11-21.md).

The TV browser and the Nuvio web player each finished the same locally served
12-second H.264 clip at 1280 × 720. Both reported zero dropped frames at
completion. Audio was muted. Hardware decoding, longer playback and 4K are
**OPEN**. The playback counters measure delivery to the browser player.

## Reading diagnostic logs on this build

**VERIFIED** against the local firmware files. These observations describe
code and configuration. Parser dispatch below was checked offline. Device
observations follow the table.

| Evidence | Interpretation |
| :--- | :--- |
| `DebugScript.txt` basename in `libplat.so` | Four direct references belong to the file-existence check and two to the reader. The search directories in order are `/media/sda1`, `/media/sdb1`, `/mtd_apdat` and `/tmp`. The menu parser references a separate help string. |
| `?` and `:q` | The parser rewrites a leading question mark to `:h`. In the inspected dispatch table the entries for lowercase `q` and `h` both reach the help block at ELF virtual address `0x1253cc`. The help describes `q` as quit. That branch sets no worker stop flag. End of file alone does not guarantee a single pass. |
| `sleep` and numeric entries | The file reader consumes the lowercase delay token and its decimal argument before menu dispatch. A numeric selection inside a submenu depends on the active table. A number alone cannot identify the action. |
| First dated line in `log.txt` | The USB mount script writes the start line before handing the selected log path to the driver. That line alone establishes only that the script wrote it. |
| Repeated `[TIMESTAMP]` lines | A separate startup helper checks for the marker and log on `/media/sda1` during a limited startup window, then appends about every two seconds. The mount script can write the start line on a different mount. |

For offline comparison, the SHA-256 of the inspected `libplat.so` is
`959facee65eea4a09592b56238b33bfa764cef4b2e6108af482d15d71ae00508`.
The help branch and the reader are in `_DBG_ProcMenu` and `_DBG_TaskScript`.

The offline inventory contains 268 menu tables across 14 libraries.
Registration calls and linked subtables account for 218 of them. Which
tables were visible in the running menu remains **OPEN**.

**REPORTED**, 20 November. The TV identified the connected volume as

## Source availability and native video

**VERIFIED** against the archive received for this model and firmware on
20 November. The 11,309,754-byte NT72690 source delivery contained ALSA
lib 1.1.8, libgphoto2 2.5.31, libtool 2.4.6 and readline 8.0. It contained
no Linux kernel tree, board defconfig or device-tree sources. This inventory
applies to that delivery only. Archive SHA-256:
`c57d6e7ccb513e3c126509472d8b5a60838e17742b16e3818b274440e2b96c7f`.

**VERIFIED in an ARMv7 VM**, using this firmware's 32-bit hard-float
userspace libraries. The OpenMAX core initially failed to resolve
`pthread_join`. A pthread-linked host obtained the
`OMX.SDP.video_decoder.mfc0` component. Its transition to Idle failed when
the decoder could not open `/dev/video10` and `/dev/video11`. It remained
in Loaded. Two software-decoder versions independently produced identical
reference frames from the two-frame test clip. Native hardware decode and
display of those frames on the TV remain **OPEN**.

**VERIFIED offline and in an ARM VM.** The inspected Philips root filesystem
contains the GNU hard-float loader path `/lib/ld-linux-armhf.so.3`. The musl
loader path requested by the owner's ARM display probe,
`/lib/ld-musl-armhf.so.1`, is absent from that image. The VM used selected
Philips userspace files and a generic Linux 6.6 kernel. The same probe
produced the following results as its guest libraries changed.

| Guest libraries | Observed result |
| :--- | :--- |
| Firmware subset without the musl loader | The shell reported the probe as missing and returned 127 in both baseline runs. The executable was present. |
| Private musl runtime without zlib | The loader reported a missing `libz.so.1`. The invocation returned status 127. |
| Private musl runtime with zlib | In two completed runs the probe enumerated zero display cards, connectors and framebuffers and exited with status 2. |

These runs establish which libraries the probe needed to reach display
enumeration in that guest. The libraries available on the running TV and
the probe's behaviour with Philips display hardware remain **OPEN**.

As a separate reference, two builds of the VIZIO FUR8.2 Linux 5.4.249 tree
produced 19 pairwise-identical artifacts, including three device trees and
twelve modules. Compatibility with the fitted Philips board remains **OPEN**.
